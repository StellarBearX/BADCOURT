# BADCOURT — HUD สไตล์เกมสำหรับคลิปแบดมินตัน

ใส่ HUD สไตล์เกมให้คลิปแบดมินตันแนวตั้ง (ถ่ายจากหลังเส้นหลัง กล้องถือมือ) ด้วยคำสั่งเดียว

```bash
pip install -e .          # ครั้งแรกครั้งเดียว (ต้องมี ffmpeg ในเครื่อง)
hud คลิป.mp4              # -> คลิป_HUD.mp4 + คลิป_HUD_report/index.html + คลิป_hud.yaml
```

ตัวเลือก: `--no-video` (วิเคราะห์ + รายงานอย่างเดียว เร็ว), `--fresh` (ล้างผลวิเคราะห์เดิม),
`--config ไฟล์.yaml`, `-o ชื่อไฟล์ออก.mp4`

## บนจอ
- วงแหวนใต้เท้าที่เอียงตามพื้นคอร์ท (วาดบนระนาบคอร์ทผ่าน homography) + ป้ายชื่อเหนือหัว (ไม่ทับกัน)
- เป้า **LOCK ON** ตามลูก บอกคนตีล่าสุดและ km/h
- แถบบน RALLY TIME / RALLY COUNT / SHOT SPEED (+ RALLY n/N ถ้าคลิปมีหลายแรลลี)
- แผงล่างซ้าย: พลังกาย (STAMINA) + ระยะวิ่งของ 4 คน
- แผงล่างขวา: COURT MAP มุมบน (ตำแหน่ง 4 คน + ลูกศรช็อตล่าสุด)

## ขั้นตอน (badhud/)
| ขั้น | ไฟล์ | วิธี |
|---|---|---|
| 1 เตรียม | `prep.py` | ffmpeg ย่อ/ขยายเป็น 1080x1920, แยกเสียง, หา onset ช่วง 2–8 kHz |
| 2 กล้องขยับ | `camera.py` | LK optical flow บนเพดาน/ผนัง (เหนือพื้น นอกกรอบคน) → homography ระหว่างเฟรม |
| 3 คน | `people.py` | YOLO11m + ByteTrack ทุกเฟรม imgsz 1280 (ใช้ GPU ถ้ามี) |
| 4 คอร์ทเฟรมแรก | `court.py` | หน้ากากเส้นขาว (ridge) → Hough → จุดลู่ของเส้นแนวยาว → สองเส้นนอนล่างสุด = เส้นหลัง 0 ม. / เส้นเสิร์ฟยาว 0.76 ม. → จับคู่เส้นแนวยาวกับ x = 0, .46, 3.05, 5.64, 6.10 ด้วย cross-ratio → homography → ดึงเข้าหาเส้นขาว |
| 5 คอร์ททุกเฟรม | `court.py` | ทำนายจากการขยับกล้อง → ดึงเข้าหาเส้นขาวเฉพาะครึ่งใกล้ และอ่านคอร์ทใหม่จากภาพทุก 2 เฟรม เลือกอันที่ทับสีขาวมากกว่า; คอร์ทถูกแทนด้วยท่าทางกล้องจริง (หมุน + ตำแหน่ง, โฟกัสคงที่) จึงบิดเบี้ยวไม่ได้ แล้วทำให้นิ่งในพิกัดที่ชดเชยกล้อง |
| 6 ใครเป็นใคร | `identity.py` | สีเสื้อช่วงอก (เข้ม/อ่อน/ผิว) + ฝั่งคอร์ท + ตำแหน่งเดิม (Hungarian); ฝั่งไกลแยกด้วยสีรองเท้า |
| 7 ลูก | `ball.py` | จุดสว่างเล็กที่สว่างกว่าเฟรม ±3 และ ±10 (ชดเชยทั้งแบบพื้นหลังและแบบพื้นคอร์ท) → seed+extend เป็น tracklet → เลือกเส้นทางเดียวที่เปลี่ยนทิศได้เฉพาะตรงไม้ของ 4 คน |
| 8 ช็อต | `shots.py` | ลูกกลับทิศ/ถูกเตะออกข้างตรงไม้ + เสียงตีตอนมองไม่เห็นลูก → DP เลือกลำดับที่สลับฝั่งเสมอ; คนตี = คนในทีมที่ใกล้ลูกกว่า; ความเร็ว = (e^(kD) − 1)/(kT), k = 9.81/6.8² |
| 9 วาด | `render.py` | Pillow + ฟอนต์ Kanit (OFL) แล้วใส่เสียงเดิม |
| 10 รายงาน | `report.py` | เส้นคอร์ท 8 เฟรม, ทุกช็อต (ตอนตี/+0.2 วิ), ช่วงไม่มีช็อตนาน, ใครเป็นใคร, คำเตือน (>250 หรือ <25 km/h, ห่าง <0.33 หรือ >2.4 วิ, ฝั่งเดียวกันตีติดกัน) |

ผลวิเคราะห์ที่ช้า (คน, กล้อง, คอร์ท, ลูก) เก็บไว้ใน `<คลิป>_hudwork/` รันซ้ำหลังแก้ config จึงเร็ว

## แก้ผลผ่านไฟล์ `<คลิป>_hud.yaml`
```yaml
players:                       # ชื่อ / ฝั่ง / ลักษณะ / สี
- {name: พี, side: near, shirt: dark, color: '#36C8FF'}
shots_add:                     # เพิ่มช็อต (player = ชื่อ หรือ near/far)
- {t: 12.34, player: เอิร์ท}   # เวลาเดียวกับช็อตที่ตรวจเจอ = แก้คนตี
shots_remove: [15.2]           # ลบช็อตที่ใกล้เวลานี้ที่สุด (±0.2 วิ)
rally_end: 47.8                # หรือ rallies: [[3.6, 10.3], [19.4, 23.4]]
```

## ข้อจำกัดที่รู้
- ลูกมองเห็นชัดเฉพาะตอนลอยตัดเพดาน/ผนัง ช่วงที่อยู่หน้าผู้เล่น/ตาข่ายมักหาย → ใช้เสียงช่วย
- เพราะเป็นภาพ 2 มิติ ผู้เล่นฝั่งไกลที่ยืนซ้อนหลังผู้เล่นฝั่งใกล้ใช้ "โซนไม้" เดียวกัน การแยกว่าใครตีจึงอาจผิด → แก้ผ่าน `shots_add`
- ช็อตสุดท้ายของแรลลีแสดงความเร็วเฉพาะเมื่อเห็นลูกตกพื้น (ไม่งั้นแสดง ---)
